# PostTopOpt

Состояние документации: 9 ноября 2026 года.

C++20 статическая библиотека извлечения изоповерхностей на регулярной декартовой
сетке для исследования постобработки результатов топологической оптимизации.
Сам оптимизатор, импорт CAE-плотностей и графический просмотрщик пока не реализованы.

## Реализованные методы

| Ключ примера | API | Размещение вершин | Грани |
| --- | --- | --- | --- |
| `dc` | `dualContour` | QEF по пересечениям рёбер и нормалям в них | Четырёхугольники |
| `emilk` | `dualContourEmilk` | QEF по линеаризациям поля в уникальных концах пересечённых рёбер | Четырёхугольники |
| `mc` | `marchingCubes` | Интерполяция на рёбрах, классическая таблица 256 случаев | Треугольники |

Оба DC используют общий Eigen SVD, связность и параметры QEF.
Доступны свободная/ограниченная ячейкой задачи с регуляризацией или без неё.
По умолчанию: `regularization=1e-6`, `constrainToCell=true`.
Настройки QEF доступны через C++ API, но пока не через командную строку.
MC градиент и QEF не использует.

## Сборка и запуск

Необходимы CMake 3.20+, Git и компилятор C++20.
Eigen 3.4.1 загружается при первой конфигурации.
Для MinGW нужны компилятор и `mingw32-make` в PATH.

Из корня проекта, PowerShell:

```powershell
cmake -S . -B build -G "MinGW Makefiles" -DCMAKE_BUILD_TYPE=Release
cmake --build build --parallel 4
.\build\PostTopOptGyroid.exe --method dc
.\build\PostTopOptGyroid.exe --method emilk
.\build\PostTopOptGyroid.exe --method mc
```

Без пути результаты сохраняются в корневую `results/`:
`gyroid.obj`, `gyroid_emilk.obj`, `gyroid_mc.obj`.
Каталог создаётся автоматически. Явный путь имеет приоритет.
Все пять фигур и параметры сеток описаны в [examples/README.md](examples/README.md).

Для Visual Studio нужен отдельный каталог сборки и соответствующий генератор.
Исполняемые файлы находятся в подкаталоге конфигурации; для CTest указывается,
например, `-C Release`. Проверки проекта на MSVC пока не выполнены.

## Проверки

```powershell
# Весь зарегистрированный набор; запускает также исходные примеры.
ctest --test-dir build --output-on-failure

# Только проверки новых методов и сравнение трёх выбранных фигур.
ctest --test-dir build -R "^(ExtractionMethodsTest|InvalidMethodCLI|Compare.*)$" --output-on-failure
```

Выбранный прогон из 11 тестов успешно выполнен на GCC/MinGW:
объединение сфер, блок с каналами и гироид каждым методом, алгоритмические
проверки и ошибочный ключ CLI. Это не полная сертификация геометрии.
Результаты и обнаруженные дефекты: [сравнение методов](docs/method_comparison.md).

## Структура

| Каталог/файл | Назначение |
| --- | --- |
| `include/` | Grid, ContourOptions, Mesh, API алгоритмов и OBJ |
| `src/` | Два DC, независимый MC, таблица MC и экспорт |
| `examples/` | Пять полей и общий запуск с выбором метода |
| `tests/` | Численные и интеграционные проверки |
| `docs/` | Математика, решения, эксперименты и обзор источников |
| `results/` | OBJ для просмотра и синхронизации Git |
| `third_party/` | Происхождение и лицензия таблицы MC |
| `build/` | Локальная сборка и загруженные зависимости; исключены из Git |

`SurfaceExtraction.h` объединяет выбор метода; `Mesh` хранит вершины,
четырёхугольники и треугольники; `ObjWriter` не зависит от способа извлечения.

## Ограничения и происхождение

Вход — функция поля и, для DC, необязательный градиент.
Нет импорта плотностей, STL/STEP, octree, Surface Nets, MDC, TMC/MC33,
автоматического исправления топологии и самопересечений.
Границы AABB автоматически не закрываются.
Нулевой/некорректный градиент в точке ограничения DC приводит к ошибке.
Для emilk необходим фактический градиент поля, если оно не является SDF.

Базовый DC написан самостоятельно по постановке, сопоставленной с
BorisTheBrave/mc-dc; это не дословный перенос Python.
Emilk-подобный вариант адаптирует идею угловых ограничений, но сохраняет наш
решатель. Таблица MC взята из scikit-image v0.25.2 с сохранением
[атрибуции и лицензии](third_party/README.md); runtime-зависимости от Python нет.

## Дополнение: CGAL, 10 ноября 2026

Добавлен необязательный метод cgal-dc. Собственные DC, emilk и MC сохранены.
CGAL имеет отдельный решатель QEF и соглашение о нуле; описание общего

## Импорт PLY (необязательная VTK)

Добавлен отдельный модуль и программа `PostTopOptPlyImport` для чтения Stanford PLY и диагностики сетки. Включение: `POSTTOPOPT_WITH_VTK=ON`. Код ещё не проверен сборкой и запуском. [Настройка VTK, команды и ограничения](docs/ply_import.md).

## Единый API и данные элементов

Новый вход `PostTopOpt.h` поддерживает analytic Field и CellScalarVolume, с отдельными изменяемыми настройками backend. ParaView AMR включается через POSTTOPOPT_WITH_PARAVIEW и требует SDK ParaView. [Архитектура и ручная проверка](docs/architecture.md). Эта архитектурная итерация ещё не проверена сборкой и запуском.

Сравнение PLY через плотности: цель `PostTopOptPlyDensity`, режим `--method all`, регулируемая ширина перехода, общий массив данных и CSV-отчёт. [Команды и результаты](docs/ply_density.md).

Готовые поля плотностей и измерение DC/ParaView: `PostTopOptBenchmark`. [Банк заданий и методика](docs/benchmark.md).
