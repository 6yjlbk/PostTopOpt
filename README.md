# PostTopOpt

C++20 библиотека извлечения изоповерхностей методами Dual Contouring, emilk-подобным DC и классическим Marching Cubes на регулярной декартовой сетке.

## Сборка и запуск

Необходимы CMake 3.20+, компилятор C++20 и Git. Eigen 3.4.1 загружается CMake при первой конфигурации.

```powershell
# MinGW: каталог компилятора должен присутствовать в PATH
cmake -S . -B build -G "MinGW Makefiles"
cmake --build build
ctest --test-dir build --output-on-failure
.\build\PostTopOptDemo.exe results/sphere.obj
```

Для Visual Studio используется отдельный каталог сборки и генератор Visual Studio; при запуске CTest указывается конфигурация, например `ctest --test-dir build-msvc -C Debug`. Сборка MSVC в текущей проверке не выполнялась.

## Интерфейс

- `DualContouring.h`: `Grid`, `ContourOptions`, функции поля/градиента и `dualContour` / `dualContourEmilk`.
- `Mesh.h`: координаты вершин, индексы четырёхугольных и треугольных граней.
- `ObjWriter.h`: независимый экспорт OBJ.
- `examples/sphere.cpp`: пример извлечения сферы.
- `tests/dual_contouring.cpp`: численные, топологические и интеграционные проверки.

Вход — функция скалярного поля и необязательная функция градиента. При отсутствии градиента используются центральные разности. Отрицательное значение относительно изоуровня означает внутреннюю область; равенство относится к внешней стороне. Шаг задаётся независимо по трём осям. Это интерфейс непрерывного поля: чтение файлов плотностей и их интерполяция пока не реализованы.

QEF решается через Eigen SVD относительно среднего пересечений. По умолчанию используется регуляризация 1e-6 и ограничение вершины ячейкой с перебором активных ограничений. Эти параметры доступны через `ContourOptions`.

## Ограничения

Реализован базовый DC с одной вершиной на активную ячейку. Нет octree, manifold-модификации, автоматического устранения самопересечений и закрытия поверхности на границе области. Нулевая или некорректная нормаль приводит к исключению. Формат вывода — OBJ с четырёхугольниками (DC) или треугольниками (MC); STL и общая триангуляция DC пока не реализованы. Классический MC использует фиксированную таблицу без MC33. Проверки на сфере не являются доказательством корректной топологии для любых полей.

## Происхождение алгоритма

Схема сопоставлена с учебным [BorisTheBrave/mc-dc](https://github.com/BorisTheBrave/mc-dc), в частности `dual_contour_3d.py` и `qef.py`. C++ код написан самостоятельно по математической постановке DC; это не дословный перенос Python-исходников. Права на коммерческое заимствование исходного Python-кода не подтверждены. Подробности методов и лицензий приведены в `docs/algorithm.md`.

## Сравнение методов

Во всех примерах доступен ключ `--method dc|emilk|mc`, по умолчанию `dc`.
См. [команды, постановку и ограничения](docs/method_comparison.md).
`MarchingCubes.h` — независимый метод; `SurfaceExtraction.h` — общий переключатель.
