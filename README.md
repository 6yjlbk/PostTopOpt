# PostTopOpt

PostTopOpt — C++20-библиотека построения изоповерхности для постобработки топологической оптимизации. На входе — регулярная сетка и объёмная доля материала (volume fraction, VF) в каждом элементе. На выходе — полигональная поверхность `Mesh`, которую можно сохранить в OBJ.

Поддерживаются собственные DC, emilk-подобный DC и Marching Cubes, а также опциональные CGAL DC и ParaView `vtkAMRDualContour`. Библиотека использует Eigen и собирается CMake. Графического интерфейса и самого оптимизатора в проекте нет.

## Быстрый запуск

PowerShell из корня проекта; preset рассчитан на установленный MSYS2 UCRT64 в `C:/msys64` и совместимые SDK CGAL/ParaView/VTK:

```powershell
$env:PATH="C:\msys64\ucrt64\bin;$env:PATH"
cmake --preset release
cmake --build --preset release
.\build\release\PostTopOptRun.exe --input gyroid --cells 64 --method compare --output-dir results/gyroid-64
```

Команда сравнивает DC и ParaView на одном массиве VF. Benchmark включён по умолчанию: пять повторов, отдельный профиль и два OBJ. Для одного построения без CSV-отчётов указать `--benchmark false`. Каждый запуск требует новой или пустой папки результатов.

Вместо `gyroid` можно передать `data/models/Armadillo.ply` или сохранённый CSV/PTOV1. Для готового массива `--cells` не указывается. Подготовка PLY/аналитики создаёт синтетические VF; это выборка функции в центрах элементов, а не точное интегрирование занятого объёма.

## Структура репозитория

| Папка | Назначение |
| --- | --- |
| `include`, `src` | Публичный API и реализация библиотеки |
| `apps` | Единый CLI, основной аналитический банк и ввод/вывод VF |
| `apps/legacy` | Прежние примеры прямого аналитического входа и специальные эксперименты |
| `data/models`, `data/volumes` | PLY и сохранённые массивы VF |
| `results` | Настройки, CSV и OBJ отдельных запусков |
| `build/release`, `build/debug` | Сборки; `build/legacy` — нерабочий архив прежних кэшей |
| `tests`, `docs`, `third_party` | Проверки, документация, происхождение и лицензии стороннего кода |

Генерируемые результаты и большие новые массивы не добавляются в Git автоматически. Наличие успешно построенного Mesh не гарантирует правильную топологию: проверки качества описаны отдельно от замеров скорости.

Таблица MC заимствована из scikit-image с сохранением [атрибуции и лицензии](third_party/README.md). Собственный DC — самостоятельная C++ реализация по постановке, сопоставленной с учебным BorisTheBrave/mc-dc; emilk-подобный вариант меняет источник QEF-плоскостей, сохраняя наш решатель.
