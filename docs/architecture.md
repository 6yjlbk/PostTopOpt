# Устройство PostTopOpt и математическая модель

PostTopOpt строит полигональную поверхность по скалярному полю на регулярной пространственной сетке. Основной сценарий — постобработка результатов топологической оптимизации: из распределения объёмной доли материала получить границу тела для просмотра и дальнейшей обработки.

Библиотека не решает задачу оптимизации и не строит конечные элементы. Её результат — поверхностная сетка `Mesh`: координаты вершин и индексы треугольных или четырёхугольных граней.

## 1. Входные данные и общий процесс

Объёмная доля, **volume fraction (VF)**, — безразмерная величина от 0 до 1. Значение 0 соответствует отсутствию материала, 1 — полностью заполненному элементу. Промежуточные значения могут быть результатом оптимизации либо выбранной модели перехода между материалом и пустотой. Обозначение $\rho$ в формулах ниже означает VF, а не массовую плотность.

Общий вход сравниваемых методов — геометрия регулярной сетки и массив $\rho_e$, одно значение на элемент:

```text
PLY → знаковое расстояние → выборка VF ───┐
Аналитическое выражение → выборка VF ────┼→ Grid + CellScalarVolume
CSV/PTOV1 → чтение готовых VF ───────────┘             ↓
                                             выбранный метод
                                                     ↓
                                            Mesh → отчёт и OBJ
```

Источники отличаются только подготовкой массива. Каждый метод получает один и тот же подготовленный массив; менять модель или повторно вычислять SDF между методами не требуется.

### Регулярная сетка

`Grid` в `include/Field.h` содержит:

| Поле | Смысл |
| --- | --- |
| `origin` | Координаты нижнего угла области |
| `spacing` | Шаг по каждой оси; шаги могут различаться |
| `cells` | Число элементов по трём осям |

Узлов по каждой оси на один больше, чем элементов. Центр элемента с индексами $(i,j,k)$:

$$
\mathbf x_e=\mathbf o+\mathbf h\odot(i+\tfrac12,\ j+\tfrac12,\ k+\tfrac12).
$$

Здесь $\mathbf o$ — origin, $\mathbf h$ — spacing, $\odot$ — покоординатное умножение. `CellScalarVolume` хранит `Grid` и `std::vector<double> values`. Индекс элемента в массиве:

$$
\operatorname{index}(i,j,k)=(iN_y+j)N_z+k.
$$

Ось z меняется быстрее всего. Ошибка в порядке индексов меняет геометрию, даже если размер массива правильный.

### Как VF элементов превращаются в поле

Для собственного DC недостаточно только списка $\rho_e$: нужны значения в узлах, внутри рёбер и рядом с ними для производных. Временная реконструкция `linearCellField` задаёт непрерывное поле **трилинейной интерполяцией между центрами элементов**. По каждой оси выбираются два соседних центра; их восемь комбинаций дают взвешенную сумму:

$$
\rho(\mathbf x)=\sum_{a,b,c\in\{0,1\}}w_a(t_x)w_b(t_y)w_c(t_z)\rho_{abc},
\qquad w_0(t)=1-t,\quad w_1(t)=t.
$$

За крайними центрами используется постоянное продолжение по соответствующей оси. Это не простое переименование элементных значений в узловые и не интерполяция функциями формы конечного элемента. Сохранение интегрального объёма материала такой реконструкцией не гарантируется.

Для порога материала $\tau$ строится поле

$$
f(\mathbf x)=\tau-\rho(\mathbf x).
$$

Изоповерхность — $f=0$, то есть $\rho=\tau$. Собственный DC считает материалом область $f<0$. По умолчанию $\tau=0.5$.

В будущем продукт может передать другую реконструкцию через `Field` и `Gradient`, например с функциями формы. Типы `Field` и `Gradient` — вызываемые функции от `Vec3`; типы внешних библиотек для этого не нужны.

## 2. Откуда берутся тестовые VF

**PLY.** VTK читает поверхность, триангулирует её и проверяет рёбра. SDF-адаптер отклоняет открытые модели, неманифолдные рёбра и вырожденные треугольники. Ориентация подготавливается на копии в памяти; исходный PLY не изменяется. Затем `vtkImplicitPolyDataDistance` вычисляет знаковое расстояние $d$: отрицательное внутри, положительное снаружи.

В CLI применяется переход:

$$
\rho(\mathbf x)=\operatorname{clamp}\left(\frac12-\frac{d(\mathbf x)}{w},0,1\right),
\qquad w=h\,\texttt{widthCells}.
$$

В узком слое толщиной $w$ плотность плавно меняется от 1 до 0. Значения выбираются в центрах элементов. После этого собственный DC работает с реконструкцией полученного массива, а не запрашивает исходный SDF.

**Аналитические задания.** `apps/AnalyticModels.cpp` вычисляет знаковую меру принадлежности фигуре, положительную внутри материала, и переводит её в диапазон [0,1] через ограниченный линейный переход. Весь основной банк расположен в одном файле. Его периодические задания — гироид, каналы, стержневая решётка и оболочки; простые контрольные фигуры — сфера, тор, объединение сфер, блок с каналами и конус.

В обоих случаях это **синтетические VF — выборка функции в центре элемента**, а не точная доля занятого геометрией объёма элемента. Точные VF потребовали бы интегрирования по элементам. Проверка замкнутости PLY по рёбрам также не доказывает отсутствие самопересечений и правильность знака для любых вложенных оболочек.

## 3. Как работает собственный Dual Contouring

1. Вычислить и сохранить значения $f$ во всех узлах регулярной сетки.
2. Найти рёбра, концы которых находятся по разные стороны нуля. Ячейка с одинаковым знаком во всех восьми узлах пропускается.
3. На пересечённых рёбрах найти точки $\mathbf p_i$ и нормали $\mathbf n_i$. Это данные Эрмита.
4. Для каждой активной ячейки найти одну вершину по QEF — сумме квадратов ошибок относительно касательных плоскостей.
5. Вокруг каждого внутреннего пересечённого ребра соединить вершины четырёх соседних ячеек в четырёхугольник.

Таким образом, вершина DC относится к ячейке, а грань — к ребру исходной сетки. В Marching Cubes наоборот: вершины находятся непосредственно на рёбрах, а треугольники выбираются по таблице конфигураций.

### Пересечения и нормали

При `bisection=true` корень на ребре ищется бисекцией: до 10 итераций, с остановкой по невязке поля. Для нулевого изоуровня допуск — $10^{-7}$. Точные корни на концах сохраняются. При `false` используется линейная интерполяция значений концов.

Нормаль получается нормированием градиента. Если `Gradient` не передан, используются центральные разности. В едином CLI шаг разностей — $10^{-3}\min(h_x,h_y,h_z)$. Нулевой или некорректный градиент вызывает исключение: скрытой подстановки произвольной нормали нет.

### QEF: геометрия и решение

Единичная нормаль и точка задают плоскость $\mathbf n_i^T(\mathbf x-\mathbf p_i)=0$. Вершина ячейки минимизирует

$$
E_\lambda(\mathbf x)=\sum_i[\mathbf n_i^T(\mathbf x-\mathbf p_i)]^2
+\lambda\|\mathbf x-\mathbf c\|_2^2.
$$

Первое слагаемое притягивает вершину к касательным плоскостям. Второе — регуляризация, удерживающая её около средней точки пересечений $\mathbf c$. Это помогает при почти параллельных нормалях и недостатке независимых ограничений. Но регуляризация меняет минимум задачи; коэффициент не нормируется на число плоскостей.

Решение вычисляется относительно $\mathbf c$, чтобы не привязывать недоопределённые направления к мировому началу координат. Для $\mathbf y=\mathbf x-\mathbf c$:

$$
\min_{\mathbf y}\left\|
\begin{bmatrix}A\\\sqrt\lambda I\end{bmatrix}\mathbf y-
\begin{bmatrix}\mathbf b\\0\end{bmatrix}
\right\|_2^2,
\quad A_i=\mathbf n_i^T,\quad b_i=\mathbf n_i^T(\mathbf p_i-\mathbf c).
$$

Основной решатель — Eigen JacobiSVD. SVD позволяет работать и с линейно зависимыми ограничениями. В одномерных подзадачах оптимизированного решателя используется масштабированная скалярная формула МНК.

При `constrainToCell=true` дополнительно требуется $\mathbf l\le\mathbf x\le\mathbf u$, где $\mathbf l,\mathbf u$ — границы ячейки. Допустимый свободный минимум возвращается сразу. Иначе рассматриваются грани, рёбра и углы: у каждой координаты три состояния — свободна, на нижней или на верхней границе. Всего до 27 состояний. Часть подзадач отсекается по нижней оценке ошибки на плоскости грани. Это решение ограниченной задачи, а не простое обрезание координат свободного решения.

Рабочие настройки: `regularization=0.001`, регуляризация, ограничение ячейкой и бисекция включены. Все параметры изменяемы. `optimizeQef=false` оставляет контрольный решатель; `cacheHermite=false` отключает кэш общих рёбер.

### Emilk-подобный вариант

Связность и QEF-решатель общие с DC, но плоскости формируются по уникальным углам пересечённых рёбер. Для угла $\mathbf q$ используется линеаризация

$$
\nabla f(\mathbf q)^T(\mathbf x-\mathbf q)+f(\mathbf q)=0.
$$

Поэтому здесь важна величина градиента, а не только его направление. Проекция на такую плоскость не является точной ближайшей точкой поверхности. Пересечения рёбер всё ещё нужны для опоры регуляризации. Это адаптация идеи emilk, а не перенос его решателя.

## 4. Различия реализаций

| Метод | Вход внутри реализации | Размещение вершин и результат |
| --- | --- | --- |
| `dc` | Реконструированное поле VF | Собственный ограниченный QEF; четырёхугольники |
| `emilk` | То же поле; плоскости по углам | Общий собственный QEF; четырёхугольники |
| `mc` | То же поле; значения на рёбрах | Классическая таблица 256 конфигураций; треугольники, без QEF |
| `cgal-dc` | То же поле через адаптер CGAL | Собственный решатель CGAL; преимущественно четырёхугольники |
| `paraview-amr` | Исходный массив VF элементов | `vtkAMRDualContour`; выход преобразуется в треугольный Mesh |

Наш коэффициент регуляризации не передаётся CGAL и ParaView. У CGAL отдельные параметры, решатель и правило равенства порогу: $f\le\tau$ вместо $f<\tau$. Наличие общего входа не означает одинаковой интерполяции и одинаковой геометрии.

Адаптер ParaView создаёт один `vtkUniformGrid` в одном уровне `vtkNonOverlappingAMR`. Индексы z-fastest переставляются в принятый VTK порядок x-fastest. Массив [0,1] не умножается на 255. По умолчанию закрытие границы выключено, слияние точек включено. Это последовательный одноблочный сценарий, а не готовая поддержка произвольной AMR-иерархии или MPI.

В адаптере временно устанавливается глобальный последовательный VTK-контроллер и затем восстанавливается. Наши вызовы защищены mutex; одновременное изменение глобального контроллера сторонним кодом хоста этим не защищено.

Экспериментальный octree-вариант CGAL доступен через его настройки и старый диспетчер `extractSurface`, но не включён в пять методов нового CLI. Уточнение по знакам углов может пропускать скрытые поверхности и давать проблемы на переходах уровней. Его нельзя считать проверенной заменой регулярного метода.

## 5. Карта кода и встраивание

| Компонент | Ответственность |
| --- | --- |
| `include/PostTopOpt.h`, `src/PostTopOpt.cpp` | Выбор метода и общий API `geometry::extract` |
| `Field`, `CellScalarVolume` | Сетка, значения элементов, выборка и реконструкция поля |
| `src/DualContouring.cpp` | Узловые значения, данные Эрмита, QEF и связность собственных DC |
| `src/MarchingCubes.cpp` | Собственный MC |
| `src/CgalExtraction.cpp` | Изолированный адаптер CGAL |
| `src/ParaViewExtraction.cpp` | Изолированный адаптер ParaView |
| `src/PlyImporter.cpp`, `src/PlyDistanceField.cpp` | Чтение PLY, проверки и знаковое расстояние |
| `src/ObjWriter.cpp` | Запись готового Mesh в OBJ |
| `apps/main.cpp` | Выбор источника, подготовка VF, повторы, отчёты и экспорт |
| `apps/AnalyticModels.cpp`, `apps/VolumeIO.cpp` | Основной банк фигур и CSV/PTOV1 |
| `apps/legacy` | Сохранённые прямые аналитические примеры и специальные эксперименты |

Одна статическая цель `PostTopOpt`; имя `PostTopOptVtk` — её alias. Eigen входит в публичные типы. Типов VTK/CGAL в публичных сигнатурах нет; при включении backend появляются соответствующие зависимости сборки и линковки.

Пример для готовых элементных VF:

```cpp
#include "PostTopOpt.h"

geometry::CellScalarVolume vf;
vf.grid = grid;               // Геометрия регулярной сетки.
vf.values = elementFractions; // z-fastest, одно значение на элемент.

geometry::ExtractionSettings settings;
settings.dc.regularization = 0.001;
auto mesh = geometry::extract(geometry::Backend::Dc, vf, 0.5, settings);
```

Вызов синхронный: входной массив должен существовать и оставаться неизменным до возврата. API не хранит поле после извлечения. Для аналитического входа есть перегрузка с `Grid`, `Field` и необязательным `Gradient`; напрямую ParaView её не принимает.

Некоторые имена API пока используют `density`, например `densityField` и `densityThreshold`. В сценарии VF это исторические имена. Полного переименования публичного API ещё не было.

## 6. Пределы применимости

Одна вершина DC на ячейку не может раздельно представить несколько независимых листов поверхности внутри неё. Тонкая деталь может исчезнуть, если ни одно ребро не обнаружит смену знака. Ограничение ячейкой снижает вынос вершин, но не гарантирует отсутствия самопересечений. Малое значение QEF также не доказывает правильную топологию или малую ошибку относительно исходной поверхности.

Автоматическое исправление геометрии, сглаживание и ремешинг пока не реализованы. Измерение времени и числа граней не заменяет проверки качества поверхности.
