# План сравнительных экспериментов

Актуализировано 9 ноября 2026 года.

## Цель и исходные наблюдения

Продолжать сравнение на тех же моделях и выбирать дальнейшее направление
по воспроизводимым данным. По визуальной оценке пользователя DC и emilk
лучше выглядят на участках постоянной кривизны, чем текущий MC.
Геометрическая ошибка и разность объёмов ещё не измерены.
[Зафиксированные результаты](method_comparison.md) содержат также дефекты DC,
поэтому визуальное предпочтение не является общей оценкой пригодности.

## Первый этап: сравнить уже реализованное

Фиксировать поле и AABB, менять один фактор за раз:

1. Для dc и emilk сравнить четыре режима QEF: свободный/ограниченный,
   с регуляризацией/без неё. Реализация есть, требуется организация прогонов.
2. Для положительного λ согласовать набор значений и записывать его в отчёт.
3. Использовать грубую, среднюю и мелкую сетки, затем небольшие сдвиги сетки
   относительно неизменённой геометрии. Сохранять запас до границ AABB.
4. Сравнивать с MC на тех же узлах и изоуровне.
5. Отдельно учитывать способ вычисления градиента и gradientStep.
   На CSG-стыках нормаль может быть неоднозначной.

Сейчас CLI не принимает QEF-параметры и размеры сетки.
Нужно либо передавать их через API в экспериментальном запуске,
либо отдельно добавить конфигурацию/CLI. Такой механизм пока не реализован.

## Набор моделей

Текущая основная серия — три объединённые сферы, блок с тремя каналами и гироид.
Сфера и тор сохранены как более простые контрольные модели.
Плоскость используется в численных тестах.
Тонкие перемычки, несколько листов внутри ячейки и реальные CAE-плотности —
предлагаемые дополнительные случаи; отдельных импортируемых CAE-примеров пока нет.
Не следует переносить таблицы с отметками «проверено» из обсуждения как журнал
фактически выполненных прогонов.

## Метрики и условия их интерпретации

| Метрика | Статус и условия |
| --- | --- |
| Вершины, quads, triangles | Уже выводятся примерами |
| Время извлечения | Уже измеряется без OBJ; для сравнения нужны повторения |
| Рёбра с 1 или >2 гранями, ориентация | Разово проверены девять OBJ; общего публичного валидатора нет |
| Геометрическая ошибка | Предстоит реализовать и определить эталон |
| Объём и знаковая ошибка объёма | Предстоит реализовать после проверки поверхности |
| Самопересечения, многообразие в вершинах | Не проверены |
| Компоненты, отверстия, сохранность перемычек | Нужен отдельный анализ |
| Геометрическое качество граней | Нужны согласованные метрики и триангуляция quads |

Для $V_\mathrm{ref}>0$ сохранять обе ошибки:

$$
\delta_V=\frac{V_\mathrm{mesh}-V_\mathrm{ref}}{V_\mathrm{ref}},\qquad
\varepsilon_V=|\delta_V|.
$$

В процентах значения умножаются на 100.
Положительная $\delta_V$ означает избыток объёма относительно эталона.
Гипотезу «emilk оставляет больше материала» проверять по знаковой ошибке,
но не принимать больший объём автоматически за более точный.

Для интерпретации объёма нужна замкнутая, согласованно ориентированная поверхность
без проблемных самопересечений; для нескольких оболочек учитывать полости.
Сумма ориентированных объёмов по некорректной сетке не доказывает физический объём.
Для неплоских quads сначала фиксировать способ триангуляции.
Триангуляция может влиять и на внешний вид, и на измеренный объём.

Невязка $|f(\mathbf x)-\tau|$ является расстоянием только для подходящего SDF.
Для гироида её нельзя подписывать как геометрическую ошибку в единицах длины.
Предпочтителен независимый эталон и расстояния до него; нужно контролировать
ошибку самого эталона. Для сложных CSG/гироида точный эталон объёма ещё не выбран.

Сравнивать также грани/поверхность между вершинами, а не только значения поля
в вершинах. При визуальной проверке фиксировать масштаб, камеру, освещение,
отображение рёбер, сглаживание нормалей и способ триангуляции просмотрщика.

## Запись эксперимента

Предлагаемые поля будущего CSV/JSON:
run_id, revision, dirty_state, shape, параметры поля, origin, spacing, cells,
isovalue, method, regularization, constrainToCell, gradient_source, gradientStep,
compiler, build_type, vertices, quads, triangles, extraction_ms, metric_status,
volume_reference, signed_volume_error, geometry_error, topology_flags, output_path.

Такая таблица пока не генерируется автоматически.
Предлагаемое хранение серий: results/<run_id>/ с конфигурацией и отчётом.
Сейчас примеры используют простые имена и могут перезаписать предыдущую модель;
для отдельного эксперимента нужно явно задавать уникальный путь OBJ.

## Следующие кандидаты, пока не реализованные

| Кандидат | Зачем исследовать |
| --- | --- |
| Surface Nets | Контрольный dual-подход без Hermite QEF |
| Внешний CGAL DC | Независимое сопоставление реализации |
| TMC / MC33 | Исследование разрешения неоднозначностей и топологии |
| Dual Marching Cubes / Manifold DC | Раздельные компоненты поверхности внутри ячеек |
| Adaptive DC / octree | Локальное разрешение и сокращение сложности |

Этот порядок является предложением из обсуждения. Выбор библиотеки и
гарантии конкретного варианта требуют отдельного рассмотрения.
CGAL не подключена, новый алгоритм не выбран вместо существующих.
Геометрическая точность, топология и скорость оцениваются раздельно.

## Импорт реальных данных

Нужны файл-пример, единицы, размеры, origin/spacing, порядок индексов
и указание, где находятся плотности: в узлах или элементах.
Неструктурированная сетка требует координат узлов и связности элементов.
STL/OBJ задаёт поверхность и требует отдельного преобразования в поле.
STEP требует CAD-импорта. Ни один из этих загрузчиков сейчас не реализован.
