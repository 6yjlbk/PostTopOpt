# Сравнение методов: результаты и следующие задачи

Цель сравнения — оценить скорость и качество собственного DC при входе в виде VF элементов, сопоставив его прежде всего с ParaView. Подготовка SDF не является частью DC и рассматривается отдельно.

## Как сравнивать корректно

Методы должны получать одну сетку, один массив VF и одинаковый порог. Для исследования разрешения следует менять `cells`, сохраняя параметры фигуры. Для исследования параметра QEF — менять только его.

Время сравнивается по повторным обычным вызовам, внутренние этапы — по отдельному диагностическому вызову. Если исходный PLY долго преобразуется в VF, это не означает, что долго работает DC. Для повторного сравнения полезно сохранить VF через `--save-volume` и дальше загружать готовый массив.

Одинаковое число вершин не означает одинаковой точности. DC выдаёт четырёхугольники, ParaView в нашем адаптере — треугольники. При сравнении числа граней это различие обязательно учитывать. Полная методика текущего CLI и определения полей CSV — в [running.md](running.md).

## Что уже оптимизировано

| Изменение | Почему экономит время |
| --- | --- |
| Кэш данных Эрмита общих рёбер | Соседние ячейки повторно используют точку и нормаль вместо повторных запросов поля |
| Ранний возврат допустимого свободного QEF-минимума | Если вершина уже внутри ячейки, перебор границ не нужен |
| Отсечение граничных QEF-подзадач | Минимум на плоскости грани даёт нижнюю оценку для принадлежащих ей рёбер и углов |
| Ограниченные буферы Eigen и повторное использование векторов | Уменьшены выделения памяти на каждую активную ячейку |
| Пропуск ячеек с одинаковым знаком узлов | Не требуется обходить все 12 рёбер |
| Прямая индексация при реконструкции поля | Устранены повторные проверки уже ограниченных индексов |
| Синхронное использование входного массива без копии | Не копируется весь объём перед извлечением |

Hermite-кэш разреженный, создаётся на один вызов и применяется только к классическому DC. `Field` и `Gradient` должны быть детерминированными в течение вызова. Кэш потребляет дополнительную память; послойное ограничение памяти пока не реализовано.

Число допустимых QEF-плоскостей позволяет использовать буферы до 15×3: 12 рёбер плюс три строки регуляризации. У двух- и трёхмерных задач сохранён SVD; одномерная решается скалярным МНК. Перестановка подзадач и округление могут изменить координаты в вырожденных случаях, поэтому контрольный путь сохранён.

## Что подтверждают проверки

В прежней серии пять выбранных тестов проходили: собственный DC, набор методов, адаптер CGAL, общий API и регрессия оптимизации. `OptimizationRegressionTest` сравнивал 192 сочетания полей, регуляризации, ограничения ячейкой, бисекции и двух собственных DC; дополнительно — вырожденные плоскости и корни на концах рёбер. Связность сравнивалась точно, координаты — с относительным допуском $10^{-8}$. На банках 64³ и 96³ сравнение оптимизированного и контрольного путей проходило с более строгим допуском координат.

Это подтверждает отсутствие обнаруженной регрессии на этих данных, но не доказывает корректность на любом поле. Новая структура CLI и `ApplicationDataTest` не получили в этом обновлении повторного прогона. Редактура документации сборки и тесты не запускала.

В ранних экспериментах на объединении сфер и других аналитических полях у собственных DC обнаруживались рёбра с более чем двумя гранями и почти вырожденные четырёхугольники. Это основание проверять топологию отдельно; точные количества из старых прогонов нельзя переносить на новые настройки и разрешения.

## Следующие задачи

1. **Подтвердить качество.** Добавить общую проверку граничных и неманифолдных рёбер, вырожденных граней, ориентации и компонент связности. Для самопересечений нужна отдельная проверка.
2. **Измерить геометрическую ошибку.** Для аналитической поверхности сравнивать с независимым эталоном; для PLY различать ошибку перехода PLY → VF и ошибку извлечения из VF. Нельзя считать малый QEF мерой полной ошибки.
3. **Проверить сохранение материала.** Только после проверки замкнутости и ориентации сравнивать объём поверхности с выбранным эталоном и с $\sum_e\rho_e V_e$; это разные величины при сглаженном пороге и приближённой реконструкции.
4. **Дальше оптимизировать DC по профилю.** Кандидаты — послойный кэш, пакетная обработка QEF, специализированные запросы VF и градиента. Градиент трилинейного поля требует аккуратной обработки границ интерполяционных областей.
5. **Проверить масштабирование.** Измерять пик памяти, время на серии разрешений и реальных VF. Для многопоточности сначала определить потокобезопасность `Field`/`Gradient` и хостового VTK.

Это план, а не перечень уже реализованных возможностей. Смена численного решателя, SIMD и многопоточность требуют отдельных сравнений с контрольным вариантом и проверки качества.
