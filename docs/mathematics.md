# QEF, SVD и размещение вершин

Актуализировано 9 ноября 2026 года.
Фактическая реализация: [DualContouring.cpp](../src/DualContouring.cpp),
[параметры](../include/DualContouring.h). Обзор методов: [algorithm.md](algorithm.md).

## Геометрический смысл QEF

При единичных нормалях $\mathbf n_i$ и точках плоскостей $\mathbf p_i$:

$$
E(\mathbf x)=\sum_i[\mathbf n_i^T(\mathbf x-\mathbf p_i)]^2
=\|A\mathbf x-\mathbf b\|_2^2,\qquad
A_i=\mathbf n_i^T,\quad b_i=\mathbf n_i^T\mathbf p_i.
$$

Это ошибка относительно плоскостей, не расстояние до исходной нелинейной
поверхности. Малое E не доказывает ни геометрическую точность, ни корректную топологию.

Две независимые плоскости могут оставлять прямую минимумов.
Три плоскости дают единственную точку пересечения при линейно независимых
нормалях; одной попарной непараллельности недостаточно.
Если ограничения несовместны, минимум ошибки обычно положителен.

Пример: $x=0.3$, $x=0.5$, $y=0.7$, $z=0.4$.
Минимум равен $(0.4,0.7,0.4)$, $E=0.02$.
Плоскости y и z в этом примере не влияют на выбор x.

## Два способа сформировать плоскости

### Обычный DC

На ребре со сменой знака интерполируется пересечение $\mathbf p_i$.
В нём вычисляется градиент и единичная нормаль. Эти данные задают QEF-плоскость.
Пересечение нелинейного поля линейной интерполяцией является приближением.

### Emilk-подобный DC

Каждый уникальный угол $\mathbf q$ пересечённых рёбер даёт линеаризацию:

$$
\nabla f(\mathbf q)^T(\mathbf x-\mathbf q)+f(\mathbf q)-\tau=0.
$$

Для общего решателя используются:

$$
\mathbf n_q=\frac{\nabla f(\mathbf q)}{\|\nabla f(\mathbf q)\|},\qquad
d_q=\frac{f(\mathbf q)-\tau}{\|\nabla f(\mathbf q)\|},\qquad
\mathbf p_q=\mathbf q-d_q\mathbf n_q.
$$

Это проекция на локальную линейную модель, не точное пересечение поверхности.
Для произвольного поля требуется фактический градиент; единичного направления
недостаточно для вычисления d. Нулевой/некорректный градиент приводит к ошибке.
Для SDF с единичным градиентом деление на норму не меняет расстояние.

Меняются QEF-данные, а не только способ поиска точек Эрмита.
Количество строк может отличаться; повторяющиеся углы не получают лишний вес.
Сравнивать абсолютные значения QEF разных наборов строк как общую меру качества
нельзя без отдельного определения метрики.

## Что делает SVD

Для матрицы ограничений:

$$
A=U\Sigma V^T.
$$

Правые сингулярные векторы задают направления в пространстве координат.
Нулевое сингулярное число соответствует направлению, не определяемому
ограничениями; малое ненулевое число может означать чувствительность решения.

В свободной задаче псевдообратная даёт решение наименьших квадратов.
Уравнения $x=0.3$, $y=0.7$ не определяют z.
Решение минимальной нормы в исходных координатах — $(0.3,0.7,0)$.
Если решать относительно $\mathbf c=(0.5,0.5,0.5)$, ближайший к опоре минимум —
$(0.3,0.7,0.5)$. Это выбор среди минимумов, а не новая геометрическая информация.

В коде используется Eigen JacobiSVD с ComputeThinU/ComputeThinV.
Порог численного ранга берётся по умолчанию из Eigen; отдельной пользовательской
настройки, вывода сингулярных чисел и диагностики обусловленности пока нет.
SVD сам по себе не ограничивает вершину ячейкой и не устраняет ошибочные нормали.

Нормальные уравнения $A^TA\mathbf x=A^T\mathbf b$ здесь не решаются.
Для полного столбцового ранга $\kappa_2(A^TA)=\kappa_2(A)^2$;
их формирование может усилить численные трудности.

## Реализованные четыре режима

| Режим | regularization | constrainToCell |
| --- | ---: | --- |
| Свободная QEF | 0 | false |
| Свободная регуляризированная QEF | >0 | false |
| QEF с ограничением ячейкой | 0 | true |
| Регуляризированная QEF с ограничением | >0 | true |

Режимы доступны и для dc, и для emilk.
По умолчанию $\lambda=10^{-6}$ и constrainToCell=true.
Это текущие настройки, не результат оптимизации на промышленных данных.
MC QEF не использует.

Общая целевая функция:

$$
E_\lambda(\mathbf x)=E(\mathbf x)+\lambda\|\mathbf x-\mathbf c\|^2.
$$

Опора c — среднее интерполированных пересечений рёбер в обоих DC.
В emilk эти пересечения нужны для опоры, но не для QEF-плоскостей.
Регуляризация меняет целевую функцию; она отличается от одного лишь сдвига
начала координат. Коэффициент абсолютный, без нормировки на число плоскостей.

Для $\mathbf y=\mathbf x-\mathbf c$ решается:

$$
\min_{\mathbf y}
\left\|
\begin{bmatrix}A\\\sqrt{\lambda}I\end{bmatrix}\mathbf y-
\begin{bmatrix}\mathbf b-A\mathbf c\\0\end{bmatrix}
\right\|_2^2.
$$

При $\lambda=0$ нижние строки нулевые. Для свободной задачи SVD выбирает
минимальную норму смещения с учётом численного ранга.
При $\lambda>0$ добавляется штраф по всем направлениям, не только вырожденным.

## Ограничение ячейкой

Для box-constrained задачи перебираются $3^3=27$ состояний координат:
свободная, нижняя граница, верхняя граница.
Для каждого состояния свободная подзадача решается SVD.
Недопустимые кандидаты отбрасываются; выбирается минимум общей целевой функции.

Финальное покоординатное ограничение убирает погрешности округления.
Это не отдельный метод «сначала свободная QEF, затем CLIP».
Ограничение ячейкой не является общей гарантией отсутствия самопересечений.

## Использование API

~~~cpp
geometry::ContourOptions options;
options.regularization = 0.0;
options.constrainToCell = false;
auto mesh = geometry::dualContour(grid, field, gradient, options);
// Для другого источника плоскостей: dualContourEmilk(..., options).
~~~

CLI примеров выбирает dc/emilk/mc/cgal-dc.
Для параметров QEF нужно изменить C++ вызов; изменение одних ContourOptions
без передачи их через API не меняет результат.

## Что пока не реализовано

QR, отдельный решатель нормальных уравнений, SIMD-QEF, адаптивный λ,
пользовательские веса плоскостей, выбор опоры и порога SVD, отдельный
режим free+clip. SVD и SIMD — разные понятия: первое является разложением
матрицы, второе — способом выполнять операции над несколькими данными.
Оптимизация SIMD имеет смысл после профилирования.

Источники для дальнейшего сопоставления:
[BorisTheBrave/qef.py](https://github.com/BorisTheBrave/mc-dc/blob/a165b326849d8814fb03c963ad33a9faf6cc6dea/qef.py),
[Gildea/qef_simd.h](https://github.com/nickgildea/fast_dual_contouring/blob/master/qef_simd.h).
Они не означают наличие этих реализаций в проекте.

## Биссекция в собственных DC (11 ноября 2026)

В ContourOptions добавлен bisection=true: биссекция; false возвращает линейную
интерполяцию. Для dc меняются точки пересечения, нормали в них и опора QEF.
Для emilk меняется среднее пересечений (опора), но плоскости по углам остаются.
Настройка не влияет на MC и не заменяет отдельный bisection в CgalContourOptions.
Лимит 10 итераций и допуск по невязке max(1e-7, abs(isovalue)*1e-7) совпадают
со стандартными параметрами установленного CGAL oracle. Нулевые концы рёбер
сохраняются точно; соглашение собственных DC о знаке остаётся прежним.
Регуляризация и ограниченный решатель не изменены. Сборка и прогоны не выполнялись.
