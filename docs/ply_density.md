# Эксперимент: PLY → плотности ячеек → backend

## Постановка

Программа PostTopOptPlyDensity создаёт один массив синтетических плотностей в центрах ячеек по знаковому расстоянию d до замкнутой PLY-модели:

$$
\rho(\mathbf{x})=\operatorname{clamp}\left(\frac12-\frac{d(\mathbf{x})}{w},0,1\right),\qquad w=\alpha h.
$$

По умолчанию alpha (--width-cells) = 2, порог = 0.5. Это значения функции в центрах, не интегральные объёмные доли элементов. При смене разрешения сохраняется w/h, а не физическая ширина перехода. Координаты исходника сохраняются. Граничный запас составляет три ячейки; alpha ограничена диапазоном (0,4]. Открытые исходники отклоняются существующим адаптером.

DC, emilk, MC и CGAL используют трилинейно реконструированный массив; ParaView использует тот же массив непосредственно как cell data. Поэтому различия результата включают разные способы реконструкции. Нормали DC/CGAL — численные, gradientStep=0.001h.

## Воспроизведение

PowerShell из корня проекта:

```powershell
$env:PATH="C:\msys64\ucrt64\bin;$env:PATH"
cmake -S . -B build-density -G "MinGW Makefiles" -DCMAKE_BUILD_TYPE=Release -DCMAKE_CXX_COMPILER=C:/msys64/ucrt64/bin/c++.exe -DCMAKE_MAKE_PROGRAM=C:/msys64/ucrt64/bin/mingw32-make.exe -DCMAKE_PREFIX_PATH=C:/msys64/ucrt64 -DParaView_DIR=C:/msys64/ucrt64/lib/cmake/paraview -DPOSTTOPOPT_WITH_PARAVIEW=ON -DPOSTTOPOPT_WITH_VTK=ON -DPOSTTOPOPT_WITH_CGAL=ON -DBUILD_TESTING=OFF
cmake --build build-density --target PostTopOptPlyDensity -j 4
.\build-density\PostTopOptPlyDensity.exe examples/Armadillo.ply --cells 32 --width-cells 2 --method all --output-dir results/armadillo-density-32
```

Для увеличения разрешения менять --cells и выходной каталог. Повторная запись существующих результатов запрещена. Поддержаны --lambda, --regularization 0|1, --constrained 0|1, --bisection 0|1. Настройки собственного QEF не применяются к ParaView/MC/CGAL; переключатели ограничения/бисекции также передаются в CGAL. В режиме all необходимы включённые CGAL и ParaView.

Каждый backend сохраняет собственный OBJ; report.csv содержит геометрию сетки, ширину перехода, параметры и раздельные времена подготовки/выборки/извлечения/экспорта. Настройки QEF в CSV относятся к собственному DC; они не означают наличие этого решателя в других backend. Исходный PLY и компилятор/ветку необходимо сохранять вместе с отчётом эксперимента для полной воспроизводимости.

## Выполненная оптимизация QEF

Сначала решается свободная задача. Если её минимум принадлежит ячейке, он является минимумом той же выпуклой задачи на ячейке и возвращается немедленно. Иначе сохраняется перебор активных ограничений. Одна проверка принадлежности необходима; устранён лишний перебор граничных подзадач, а не сам контроль допустимости. Влияние на время зависит от доли ячеек с допустимым свободным решением; отдельный замер ускорения пока не выполнен.

## Дальнейшие оптимизации — предложения

1. Профилировать раздельно подготовку VTK, выборку расстояний, реконструкцию, QEF, связность и экспорт. Использовать Release и повторные запуски.
2. Исключить повторный поиск одного пересечения/градиента на общем ребре соседних ячеек; оценить стоимость памяти кэша.
3. Использовать фиксированные/ограниченные размеры Eigen и стековые буферы вместо векторов и динамических матриц для каждой ячейки.
4. Добавить аналитический градиент трилинейной реконструкции, согласовав поведение на границах интерполяционных участков. Сейчас шесть дополнительных запросов на центральные разности.
5. Убрать копирование CellScalarVolume при передаче в функциональный адаптер через отдельный безопасный view/владеющий shared_ptr API.
6. При необходимости заменить полный перебор ограничений проверяемым active-set solver. Не заменять SVD нормальными уравнениями без анализа устойчивости.
7. Распараллеливать независимые стадии только после профиля. VTK SDF callback сейчас предполагает последовательные обращения; глобальный контроллер ParaView требует отдельного внимания.
8. SIMD рассматривать после устранения повторных вычислений и динамических выделений. Не обещать ускорение без измерений.

Ни один из этих пунктов, кроме раннего возврата QEF, не реализован в этой итерации.

## Фактически выполненные прогоны — 13 ноября 2026

Release, GCC UCRT64 16.2, VTK 9.6.2, ParaView 6.1.1, CGAL 6.2. Сборка PostTopOptPlyDensity успешна. Набор CTest не запускался согласно условию пользователя: ошибок сборки/экспериментального запуска не возникло.
