# Внешние реализации и варианты Dual Contouring

Это справочный обзор для выбора алгоритмов. В PostTopOpt подключены собственные методы, CGAL DC и ParaView AMR. Остальные проекты ниже — ориентиры для исследований, а не зависимости PostTopOpt.

Сведения об условиях использования перенесены из обзора 6–8 ноября 2026 года; при редактуре документации они повторно не проверялись. Перед включением стороннего кода нужно фиксировать версию и читать лицензию именно используемых файлов и зависимостей. Доступный на GitHub исходник сам по себе не означает разрешение на коммерческую поставку.

## Чем различаются варианты

| Подход | Основное отличие от нашего регулярного DC |
| --- | --- |
| Адаптивный DC на octree | Ячейки имеют разные размеры. Экономит разрешение на простых участках; усложняет связность между уровнями |
| Manifold Dual Contouring | Разделяет компоненты поверхности в ячейке и контролирует топологию при объединении. Одна вершина на любую активную ячейку таких свойств не даёт |
| Dual Marching Cubes | Использует локальные конфигурации компонентов поверхности; dual-связность не требует именно Hermite QEF |
| Neural DC | Геометрию и связность предсказывает обученная модель вместо обычного прямого вычисления |
| Occupancy-Based DC | Получает геометрические данные дополнительными запросами непрерывной функции без её градиента |

Ограничение QEF ячейкой, SVD, SIMD и octree решают разные задачи. SVD — численный решатель; SIMD — способ ускорить операции; octree — структура пространственного разбиения. Ни один из них сам по себе не гарантирует правильную топологию.

## Основные реализации

| Проект и код | Что делает и чем полезен |
| --- | --- |
| [CGAL Isosurfacing_3](https://github.com/CGAL/cgal/tree/master/Isosurfacing_3) | Готовая C++ библиотечная реализация DC с собственным решателем. В PostTopOpt используется через отдельный адаптер; наш коэффициент регуляризации ей не передаётся |
| [ParaView AMR](https://github.com/Kitware/ParaView/tree/master/VTKExtensions/AMR) | `vtkAMRDualContour` принимает данные ячеек AMR. Наш адаптер использует один регулярный блок; это самостоятельный метод сравнения, не обёртка над нашим QEF |
| [libfive](https://github.com/libfive/libfive) | Функциональные модели и адаптивное извлечение на дереве. Более широкая система, чем конвертер массива VF |
| [Gildea DualContouringSample](https://github.com/nickgildea/DualContouringSample) | Компактный C++ пример octree DC для изучения дерева, QEF и упрощения |
| [Gildea fast_dual_contouring](https://github.com/nickgildea/fast_dual_contouring) | Извлечение на регулярной сетке с SIMD-QEF и последующее упрощение. Упрощение уже полученного Mesh не уменьшает исходный объём обхода сетки |
| [BorisTheBrave/mc-dc](https://github.com/BorisTheBrave/mc-dc) | Учебная Python-реализация регулярного DC. Алгоритмический ориентир нашего кода, не готовый эталон точности |
| [emilk/Dual-Contouring](https://github.com/emilk/Dual-Contouring) | C++ подход с ограничениями по концам рёбер. В PostTopOpt адаптирован источник плоскостей, собственный решатель сохранён |
| [dualmc](https://github.com/dominikwodniok/dualmc) | C++ Dual Marching Cubes. Кандидат для отдельного сравнения связности, а не замена решателя QEF |
| [NDC / UNDC](https://github.com/czq142857/NDC) | Python/PyTorch; обучаемое предсказание геометрии и связности, включая unsigned-постановки |
| [ODC](https://github.com/KAIST-Visual-AI-Group/ODC) | Извлечение из occupancy-функции без градиента. Для массива VF всё равно требуется определить запросы поля между отсчётами |
| [PolyMender](https://www.cse.wustl.edu/~taoju/code/polymender.htm) | Восстановление повреждённых полигональных моделей через объёмное представление и модифицированный DC |

## Теоретическая основа

[Ju, Losasso, Schaefer, Warren: Dual Contouring of Hermite Data, 2002](https://www.cs.rice.edu/~jwarren/papers/dualcontour.pdf) — исходная постановка DC с данными Эрмита и QEF.

[Schaefer, Ju, Warren: Manifold Dual Contouring, 2007](https://doi.org/10.1109/TVCG.2007.1012) — развитие с контролем топологии при адаптивном объединении. Его гарантии нельзя переносить на любой алгоритм с названием DC.

Таблица классического MC в PostTopOpt взята из scikit-image; источник и лицензионные уведомления сохранены в [third_party](../third_party/README.md).
