# Эксперимент переноса VF: указания для проверки

Модуль изолирован от integration/vtkop, рабочего адаптера и корневого CMake. Тесты не реализованы и не запущены. Проверка C++17 -fsyntax-only с заголовками VTK 9.6.2 прошла; линковка, runtime и MSVC v142 пока не проверены. Это прототип, не принятое production-решение.

## Сборка и использование

Отдельная сборка (выполняет ответственный за проверку):

```powershell
cmake -S experiments/vf_transfer -B build/vf-transfer -DCMAKE_PREFIX_PATH=C:/msys64/ucrt64 -G "MinGW Makefiles"
cmake --build build/vf-transfer
```

Использовать тот же VTK SDK, что и ParaView; не смешивать standalone VTK и несовместимый ParaView. Standalone CMake создаёт библиотеку PostTopOptVFTransfer, не исполняемый файл и не тесты. Для запуска нужен отдельный вызывающий стенд, линкующий эту цель. Никакого подключения к основному CLI пока нет.

```cpp
#include "VFTransfer.h"
#include <vtkNonOverlappingAMR.h>
using namespace posttopopt::experimental;
TransferGrid grid;
grid.origin = {-1,-1,-1};
grid.spacing = {0.05,0.05,0.05};
grid.cells = {40,40,40};
auto amr = transferVF(source, "vf", grid, VFTransferMethod::CellCenterSampling);
// Другие варианты: NodalInterpolation, VolumeWeighted.
```

Источник: непустой vtkUnstructuredGrid, линейные объёмные элементы, конечные координаты и скалярные VF в [0,1] в CellData. Геометрия должна быть корректной, без перекрытия элементов. Вход не изменяется. Результат: один блок/уровень AMR, density в CellData, x-fastest. Для AMRDualContour размеры задавать не менее трёх ячеек по оси и учитывать его граничную обработку. AMR-фильтр модулем не запускается.

CellCenterSampling берёт VF содержащего КЭ. NodalInterpolation сначала выполняет стандартное усреднение соседних элементов в узлах vtkCellDataToPointData, затем интерполяцию vtkProbeFilter. PointData источника намеренно не переносится: одноимённое узловое поле не должно подменять выбранные cell VF. Неуспешная выборка даёт density=0, coverage=0. Успешная — coverage=1, независимо от VF.

VolumeWeighted: vtkStaticCellLocator отбирает кандидатов по bounds; vtkExtractCells извлекает их; vtkBoxClipDataSet пересекает с целевой ячейкой, объёмы выходных тетраэдров суммируются с унаследованными VF. Деление на полный объём целевой ячейки. Непокрытая часть даёт ноль. coverage — сумма объёмов пересечений / объём ячейки. Поддержаны только VTK_TETRA и корректно заданные VTK_VOXEL. VTK_HEXAHEDRON (включая искажённые), wedge/pyramid и нелинейные элементы в этом режиме явно отклоняются; расширение поддержки требует отдельного решения о геометрии пересечения. Это геометрическое клиппирование в floating point, не точная арифметика. Допуск превышения coverage — 1e-6 относительно объёма ячейки; небольшие отклонения результата ограничиваются в [0,1]. Это не доказательство отсутствия перекрытий источника: предусловие обязан обеспечить вызывающий код.

coverage имеет разную семантику в режимах; напрямую сравнивать его как одну метрику нельзя. Для выборки он также не различает реальный внешний фон и отказ поиска внутри конструкции; это нужно диагностировать отдельными эталонными точками.

## Обязательная матрица тестов для передачи Testing

1. Сборка и линковка с фактически используемыми VTK/ParaView, затем MSVC 2019 v142 C++17. Проверить отдельный target без изменения integration/vtkop.
2. VF=0, VF=1 и константа 0.37 на сетке; полное, частичное и нулевое покрытие AABB. Для семплирования сравнивать константу только в успешных точках, для VolumeWeighted ожидать rho=0.37*coverage.
3. Два voxel-элемента с VF=0.2/0.8 и целевая ячейка, пересекающая их в известной пропорции. Проверить точную формулу взвешенного среднего, полный знаменатель и вклад пустоты. Три исходных элемента — дополнительный аналитический пример.
4. Один тетраэдр с известным объёмом (например единичный координатный tetra: 1/6), полностью внутри целевой ячейки; затем разрезы, касание гранью/ребром/вершиной и почти касание. Переносить/масштабировать координаты для оценки численной устойчивости. Проверить, что clip выдаёт внутреннюю часть и сохраняет VF на каждой tetra.
5. Глобальное сохранение sum(rho_j*V_j)=sum(rho_e*V_e), если целевой домен полностью покрывает исходную сетку, отдельно для тетраэдров и voxel. Для обрезанного домена сравнивать с аналитическим объёмом пересечения. Допуск выбирать по масштабу и precision, не заявлять нулевую ошибку.
6. Нодальный метод: вручную вычисленные средние в узлах двух соседних элементов и значения внутри КЭ. Проверить различие с center sampling, не ожидать сохранения объёма или исходного разрыва VF.
7. Несимметричная сетка Nx!=Ny!=Nz, разные шаги и ненулевой origin: проверить координаты центров и x-fastest индексы. Несвязные части конструкции, внутренние пустоты и тонкие элементы меньше шага сетки.
8. Неизменность source: topology, points, CellData/PointData до и после; одноимённый PointData vf не должен влиять на результат. Повторить после изменения исходного массива VF, убедиться в отсутствии устаревших значений.
9. Неверные входы: nullptr, пустая сетка, нет массива, неверное число tuple/components, NaN/Inf, VF вне [0,1], нулевой/отрицательный шаг, переполнение размеров, вырожденные tetra/voxel. Неподдерживаемый тип для VolumeWeighted должен завершаться исключением, а не переключением на sampling. Некорректную/перекрывающуюся геометрию дополнительно проверяет вызывающий код.
10. После подтверждения переноса: одинаковый vtkAMRDualContour и iso для трёх выходов. Проверить открытые/неманифолдные рёбра, компоненты, вырожденные грани, материал у границы домена. Геометрия между математически разными методами не обязана совпадать; counts не являются достаточным критерием.
11. Производительность: отдельно перенос и AMRDualContour; прогрев, повторы, пик памяти. VolumeWeighted — correctness-first: ExtractCells и clip на каждую непустую целевую ячейку дороги. Не обещать production-производительность и не запускать длительные серии без задания.

Никакой автоматической адаптивной иерархии, ghost-слоёв, MPI, кэширования соответствий или интеграции в vtkop в этом прототипе нет.

## Стенд ShapesTest: конечные OBJ после DC

Актуальный стенд строит sphere/gyroid/torus/cone как наборы tetra с VF=1, переносит каждый тремя способами на 150^3 регулярные ячейки и вызывает vtkAMRDualContour с iso=0.5, capping и merge points. Выход триангулируется и сохраняется в двенадцать OBJ: sphere_center.obj, sphere_nodal.obj, sphere_volume.obj и аналогичные gyroid/torus. Сглаживание и decimation не выполняются. Промежуточные VTU/VTI/CSV не сохраняются. Ошибка интеграла VF выводится только в консоль, порог conservation больше не блокирует визуальный эксперимент; проверки конечности и диапазона сохранены.

Исходная область [-1,1]^3: 64^3 блоков по шесть согласованных tetra, внутренние узлы детерминированно смещены на <=0.06 шага по каждой координате. Фигура выбирается по центру tetra. Это приближение границы целыми элементами, не surface-conforming mesh. Sphere r=0.65; torus R=0.48, r=0.18; gyroid |g|<0.35 с частотой 2*pi, обрезан кубом |coordinate|<0.78. Все исходные VF=1, поэтому неоднородная узловая интерполяция здесь не исследуется.

Для стенда нужен ParaView SDK с VTKExtensionsAMR. После однократной конфигурации standalone build запуск: `cmake --build build/vf-transfer --target vf-transfer-shapes`. Цель создаёт новый каталог shape-results-* и печатает пути OBJ. Обычная сборка не запускает стенд. Код подготовлен без сборки и выполнения.



Конус: основание z=-0.5, радиус 0.5, вершина z=0.5. dc_timings.txt содержит для каждой фигуры и метода время только vtkAMRDualContour::Update (steady_clock, секунды, 6 знаков); перенос VF, триангуляция и OBJ исключены. Один вызов на случай, без прогрева и повторов. AABB фиксирован [-1,1]^3, по границам тела не вычисляется; шаг целевой сетки 2/150. При 150^3 целевых ячеек VolumeWeighted выполняет значительно больше операций клиппирования. Сборка и запуск не выполнялись.


Точность VolumeWeighted: vtkBoxClipDataSet по умолчанию создаёт float-точки. В модуле установлен специализированный vtkMergePoints, выбирающий double при InitPointInsertion до вставки выходных точек. Это сохраняет double на стадиях клиппирования; тип выхода явно проверяется. Проверка coverage<=1+1e-6 сохранена. Сетки не подгоняются под округление. Исправление подготовлено без сборки и запуска; успешное прохождение требует повторной проверки пользователем.

## Автоматический AABB — 2026-11-19

makeTransferGrid(source,{Nx,Ny,Nz}) берёт min/max координат source. Шаг по оси: (max-min)/N, origin=min-2*step, итог cells=N+4. ShapesTest использует эту функцию и фактические размеры/объёмы целевых ячеек. Низкоуровневый transferVF с явно заданной grid сохранён для контролируемых экспериментов.

Проверить: разные размеры и шаги осей, ненулевой origin, запас ровно два шага, фон во внешних слоях, отсутствие двойного padding и сдвига исходной геометрии; вырожденные bounds и переполнение размеров. Старые результаты на фиксированном [-1,1]^3 не сравнивать напрямую с новыми.

## Актуальное решение: без дополнительных слоёв, EnableCapping=true

Пользователь отменил добавление padding. makeTransferGrid(source,cells) строит сетку строго по min/max source, без увеличения числа ячеек. ShapesTest уже включает EnableCapping=true. Предыдущие указания README о N+4 и двух внешних слоях более не действуют: проверять итог N, origin=min и upper=max. В integration/vtkop makeRegularGrid(points,cells) также строит tight AABB; extractVolumeSurface не расширяет вход и по умолчанию включает capping. Штатный ParaView-адаптер не расширяет массив; default capping=true. PLY default padding=0 (явный параметр запаса сохранён как опциональный). Проверить поверхность, касающуюся AABB, и capping при всех трёх методах. Capping не доказывает водонепроницаемость произвольной поверхности. После изменений прошла только проверка синтаксиса; runtime/тесты не запускались.
