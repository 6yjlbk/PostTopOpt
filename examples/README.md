# Геометрические примеры

Все примеры возвращают отрицательные значения внутри материала и сохраняют
поверхность OBJ: четырёхугольники для DC, треугольники для MC. Просмотрщик в проект не входит.

| Цель CMake | Исходник | Фигура |
| --- | --- | --- |
| PostTopOptDemo | sphere.cpp | Существующая сфера |
| PostTopOptTorus | torus.cpp | Тор с большим радиусом 1.05 и радиусом трубки 0.38 |
| PostTopOptSphereUnion | sphere_union.cpp | Объединение трёх пересекающихся сфер |
| PostTopOptDrilledBox | drilled_box.cpp | Куб с тремя цилиндрическими каналами |
| PostTopOptGyroid | gyroid.cpp | Полосовой гироид, ограниченный кубом |

Из корня проекта, PowerShell:

```powershell
cmake -S . -B build -G "MinGW Makefiles" -DCMAKE_BUILD_TYPE=Release
cmake --build build --parallel 4
ctest --test-dir build --output-on-failure
.\build\PostTopOptDemo.exe results/sphere.obj
.\build\PostTopOptTorus.exe results/torus.obj
.\build\PostTopOptSphereUnion.exe results/sphere_union.obj
.\build\PostTopOptDrilledBox.exe results/drilled_box.obj
.\build\PostTopOptGyroid.exe results/gyroid.obj
```

Без аргумента OBJ записывается в results/ в корне проекта независимо от текущей
рабочей папки. Каталог создаётся автоматически. Явный путь по-прежнему имеет
приоритет; относительный явный путь отсчитывается от текущей рабочей папки.
Путь по умолчанию задаётся CMake при сборке: после переноса проекта на другой
компьютер нужно выполнить конфигурацию и сборку заново. Для Visual Studio исполняемые файлы находятся в каталоге
конфигурации, например build-msvc/Release; CTest запускается с -C Release.

В новых примерах параметры области задаются явно через ExampleRunner.h.
Увеличение числа ячеек повышает разрешение и расход времени/памяти.
Для обоих DC нормали вычисляет ядро центральными разностями; MC градиент не использует. На стыках min/max поле
недифференцируемо: численная нормаль является приближением. Эти примеры не
гарантируют многообразие, отсутствие самопересечений или сохранение всех деталей.

Гироид задаётся g = sin(pi*x)cos(pi*y) + sin(pi*y)cos(pi*z) +
sin(pi*z)cos(pi*x). Материал: |g| < 0.28 внутри куба с половиной стороны 1.35.
Порог 0.28 не задаёт постоянную физическую толщину. Ограничение кубом входит
в само поле; это не добавление крышек алгоритмом DC.

CTest содержит исходные проверки, новые проверки методов и сравнительные запуски.
Успешное извлечение и OBJ-экспорт не являются полной проверкой топологии.

## Предлагаемые следующие задачи

1. Сравнить шаг сетки на торе и каналах: число граней, время, сохранение отверстий.
2. Для гироида сравнить толщину полосы и разрешение; отдельно проверять связность.
3. Добавить импорт регулярного массива плотностей после согласования формата.

Для импорта нужен небольшой реальный файл и описание: размеры сетки, origin,
spacing, порядок индексов, единицы и расположение значений (узлы или центры
элементов). Для неструктурированной сетки нужны координаты узлов и связность
элементов. STL/OBJ требует отдельного преобразования поверхности в поле.

Возможные будущие файлы: include/DensityGrid.h, src/DensityGrid.cpp,
include/DensityGridReader.h, src/DensityGridReader.cpp,
examples/density_grid.cpp и tests/data/ с маленькими эталонными наборами.
Это предложение; импорт сейчас не реализован.


## Выбор алгоритма

Ключ --method dc|emilk|mc доступен всем пяти фигурам; по умолчанию dc.
Например: ` .\build\PostTopOptGyroid.exe results/gyroid_mc.obj --method mc `.
Полные команды, формулы и результаты: [сравнение методов](../docs/method_comparison.md).
