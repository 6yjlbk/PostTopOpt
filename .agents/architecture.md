## 3. Проверенные факты о проекте
- `CMakeLists.txt`: C++20, статическая библиотека PostTopOpt, публичная зависимость Eigen3::Eigen; Eigen загружается через FetchContent, тег 3.4.1.
- `include/`, `src/`: публичный API и реализации библиотеки.
- `include/Mesh.h`: Vec3 — Eigen::Vector3d; Mesh хранит вершины, треугольники и четырёхугольники.
- `include/Field.h`: Grid содержит origin, spacing, cells; Field и Gradient — std::function. Индексация элементов: z fastest.
- `include/CellScalarVolume.h`: значения относятся к элементам; доступны validate, linearCellField, densityField и sampleCells.
- `include/PostTopOpt.h`, `src/PostTopOpt.cpp`: фасад Backend/ExtractionSettings/extract; перегрузки для Grid + Field и CellScalarVolume. Методы: Dc, Emilk, Mc, CgalDc, ParaViewAmr.
- `src/PostTopOpt.cpp`: ParaView принимает объём элементов напрямую; остальные методы используют densityField с учётом порога и нулевыми изоуровнями.
- `include/SurfaceExtraction.h`: параллельный API ExtractionMethod/extractSurface включает отдельный вариант CGAL octree; транзитивно включён фасадом.
- `include/CgalExtraction.h`, `include/ParaViewExtraction.h`: отдельные настройки и проверки доступности адаптеров. У CGAL собственные настройки решателя.
- `CMakeLists.txt`: CGAL, ParaView, VTK опциональны и подключаются PRIVATE к основной библиотеке; PostTopOptVtk — alias, не отдельный модуль.
- `apps/main.cpp`: PostTopOptRun; к цели подключены apps/AnalyticModels.cpp и apps/VolumeIO.cpp. Программы apps/legacy также сохраняются в сборке.
- `tests/`: алгоритмические, архитектурные, прикладные и регрессионные проверки зарегистрированы через CTest. Их содержимое подробно не изучено.
- `CMakePresets.json`: release/debug привязаны к локальному MSYS2 UCRT64; включают CGAL, ParaView, VTK и тесты.
- `AGENTS.md`: требуется совместимость GCC/MinGW и MSVC; сборки, приложения и тесты нельзя запускать до нового разрешения пользователя.

## 8. Текущее уточнение: прототип интеграции через vtkop
Эта запись уточняет прежний статус разделов 2, 4 и 7.
Пользователь разрешил попробовать реализацию согласованного контракта: vtkop является существующей VTK-прослойкой; прикладной конвейер должен находиться в основном проекте, а не внутри vtkop. Исходники vtkop недоступны и не запрашиваются повторно.
Созданы integration/vtkop/VolumeSurface.h, VolumeSurface.cpp и VtkopContract.h. Это изолированный прототип C++17: регулярная сетка и элементные VF z-fastest -> операции предлагаемого vtkop -> вершины и треугольники. Eigen в новом интерфейсе не используется. Контракт объявляет непрозрачные владеющие дескрипторы и операции; реальные реализации обёрток отсутствуют намеренно. Без их сопоставления/реализации компонент не линкуется. Не выдавать его за готовую интеграцию.
Основной конвейер сохраняет перестановку VF, один блок AMR, настройки DC, триангуляцию и смещения индексов из текущего ParaViewExtraction.cpp. Контракт передаёт контроль времени жизни, ошибок и глобального контроллера в vtkop. Существующие исходники и CMake не изменены, новые файлы не включены в сборку.
При повторном чтении обнаружены уже имеющиеся в src/ParaViewExtraction.cpp smoothing и decimation; обе compile-time опции выключены. Прототип отражает выключенное состояние и не включает постобработку.
Сборки, приложения и тесты не запускались согласно AGENTS.md; компиляция на MSVC и численная эквивалентность не подтверждены. Следующий шаг: ревью прототипа, затем отображение контракта на реальный vtkop на удалённой машине и отдельно разрешённые сборка/проверка. ## 9. Точка продолжения по просьбе пользователя
- Целевая среда: основной проект Visual Studio 2019, C++17, предположительно .vcxproj; точный toolset и SDK пока неизвестны. Финальная интеграция выполняется на удалённой машине.
- Уточнённое имя прослойки — vtkop (не vktop). Это не основной проект: в vtkop нужны только средства доступа к VTK/ParaView, прикладной конвейер находится в .h/.cpp основного проекта с подключением vtkop.
- Нужен единственный backend vtkAMRDualContour. Вход — регулярная сетка и элементные VF; пользователь подтвердил возможность передавать значения в ячейках. Выход — координаты и треугольники в памяти. PLY, аналитические модели, другие алгоритмы, CLI, экспорт и benchmark не требуются.
- VolumeSurface.h задаёт postop::RegularGrid, ExtractionOptions, Surface и extractVolumeSurface. Настройки: threshold=0.5, enableCapping=false, mergePoints=true. Вход заимствуется на время синхронного вызова, выход владеет данными; пустая поверхность допустима.
- VtkopContract.h — явно предложенный, а не обнаруженный API. Использует непрозрачные shared_ptr-дескрипторы; копирование cell scalars, сохранение времени жизни результата, обработка ошибок и защита/восстановление глобального контроллера являются требованиями будущей реализации. Зависимость от ParaView SDK остаётся обязательной.
- Пользователь одобрил попытку прототипирования, но готовность к сборке или окончательный API реального vtkop не подтверждены. Не подменять отсутствующую интеграцию фиктивными реализациями и не запрашивать повторно исходники vtkop: пользователь отказался их предоставлять.
- Все три новых файла проверены чтением. Следующая работа только по новому заданию: ревью/корректировка прототипа или сопоставление с vtkop на целевой машине. Разрешения на запуск сборок и тестов по-прежнему нет.

## 10. Реализация предложенного контракта
По явному запросу пользователя создан integration/vtkop/VtkopContract.cpp. Он реализует операции контракта через реальные VTK/ParaView классы, используя существующий ParaViewExtraction.cpp как образец. Это реализация предлагаемого API для переноса в настоящий vtkop, а не подтверждённая интеграция с неизвестной прослойкой.
Реализованы владеющие дескрипторы, копирование VF, одноуровневый AMR, настройка/вызов DC, RAII обработки наблюдателей ошибок и глобального контроллера, обход блоков, триангуляция, чтение точек и кеш индексов треугольников. Кеш исключает повторный линейный обход граней при каждом запросе, но требует дополнительной памяти. Объекты нельзя совместно изменять из нескольких потоков; mutex защищает только вызовы update данного модуля, не сторонний код хоста.
Предыдущее утверждение об отсутствии реализаций контрактных функций устарело: определения теперь есть, однако сборка/линковка с целевым SDK и эквивалентность результата не проверены. Требуются ParaView SDK и настройки его линковки/инициализации; CMake проекта не изменён. Smoothing/decimation не добавлены.
Сборки и тесты не запускались согласно AGENTS.md. Следующий шаг — отдельно разрешённая проверка сборки и сопоставление реализации с устройством реального vtkop.

## 13. Централизация проверок в vtkop
По запросу пользователя проверки входной задачи перенесены на сторону vtkop. В основном проекте намеренно оставлена проверка вместимости итоговых std::vector: она относится к объединяемому Surface, которым vtkop не владеет. Русские комментарии сохранены, UTF-8/BOM сохранены.
