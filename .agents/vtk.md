# Память агента VTK — PostTopOpt

Обновлено 2026-11-16. При продолжении сверять с фактическим кодом и SDK; заметки не заменяют проверку версии.

## 1. Роль и область ответственности

VTK/ParaView, vtkAMRDualContour, vtkNonOverlappingAMR, ячеечные VF, конвертация геометрии, производительность SMP/TBB/MPI. Различать VTK Core и расширения ParaView. Существующие DC/MC не изменять.

## 2. Текущее состояние

Задача: ускорить непосредственно vtkAMRDualContour на одном регулярном блоке, желательно без изменения ParaView и архитектуры проекта. Аудит и отдельный эксперимент переключателей завершены. Рабочий адаптер не изменён. Следующий предложенный эксперимент — обрезка пустой периферии с защитным окружением; ещё не реализован.

## 3. Проверенные факты о проекте

- `CMakeLists.txt`: find_package(ParaView REQUIRED COMPONENTS VTKExtensionsAMR), линковка ParaView::VTKExtensionsAMR. Фильтр относится к расширениям ParaView, AMR-контейнеры и SMP-инфраструктура — к VTK. Совместно используемые SDK должны быть совместимы.
- `CMakePresets.json`, обследованный `build/release/CMakeCache.txt`: Release, GCC/MSYS2 UCRT64. В обследованном установленном SDK ParaView 6.1.1 и VTK 9.6.2. Это локальный факт, не закреплённая для всех машин версия; проверять заново.
- `src/ParaViewExtraction.cpp`, paraViewDualContour(): один vtkUniformGrid в одном уровне vtkNonOverlappingAMR, cell data density в vtkDoubleArray. Перестановка полного массива z-fastest → x-fastest. VF [0,1] без масштабирования на 255.
- `include/ParaViewExtraction.h`: defaults iso=0.5, capping=false, mergePoints=true. Адаптер включает MultiProcessCommunication и устанавливает vtkDummyController. Временно заменяет глобальный контроллер и восстанавливает его; mutex сериализует весь вызов до окончания конвертации.
- Каждый вызов заново создаёт VTK-вход и фильтр. Выход проходит vtkTriangleFilter, копируется в Mesh; ошибки отслеживаются через ErrorEvent.
- Профиль адаптера: preparation включает проверки, ожидание mutex, подготовку/настройку; filter — только Update(); conversion — проверку выхода, триангуляцию и копирование. Освобождение локальных объектов после записи профиля не входит в стадии.
- `apps/main.cpp`: основной таймер extract включает подготовку VTK, Update, конвертацию и завершение вызова. Подготовка исходных VF, проверка готового Mesh, экспорт и уничтожение возвращённого Mesh вне таймера. Профиль — отдельный запуск, не разложение медианы. CLI не предоставляет рассматриваемые переключатели; check() отклоняет пустой Mesh.
- `include/CellScalarVolume.h`, `src/CellScalarVolume.cpp`: cell-associated VF, z-fastest, проверка размеров и конечности.

### Исследование реализации ParaView

Локальные .cxx не найдены. Исследован официальный тег v6.1.1; API сверен с установленным заголовком. Отсутствие дистрибутивных патчей бинарника не доказано.

Источники:
- https://github.com/Kitware/ParaView/blob/v6.1.1/VTKExtensions/AMR/vtkAMRDualContour.cxx
- https://github.com/Kitware/ParaView/blob/v6.1.1/VTKExtensions/AMR/vtkAMRDualGridHelper.cxx

Фильтр: DoRequestData():755–766 и ProcessBlock():910–964 — последовательные циклы блоков и z/y/x. В изученных .cxx нет SMP/TBB/OpenMP/std::thread. Выбор backend SMP не распараллеливает основной цикл.

ProcessDualCell():1054–1060 повторяет получение указателя и dispatch типа для каждой ячейки, затем читает восемь VF типизированно. Ранний выход для cubeCase=0 и для 255 при BoundaryBits=0. Пропуска целого блока по диапазону VF в ProcessBlock нет. Locator содержит четыре массива vtkIdType по объёму блока и переиспользует ID общих рёбер.

ProcessBlock():862–877,966–980: MergePoints=false не отключает внутриблочный locator; изменяет владение и межблочное согласование. MergePoints не объединяет точки между процессами.

InitializeRequest():702–720: MultiProcessCommunication=false передаёт helper nullptr. В helper есть безусловное разыменование Controller, например ComputeGlobalMetaData():2792. Не считать безопасным переключателем ускорения.

DegenerateCells отвечает за переходы уровней. SkipGhostCopy касается ghost-обменов, не всех копирований; в helper есть условные локальные DeepCopy. Helper пересоздаётся при каждом выполнении запроса. MPI требует нескольких распределённых блоков; один блок автоматически не разделяется. Общие Points/Faces/BlockIds, атрибуты и locator исключают простой безопасный parallel-for.

## 4. Принятые решения

Согласовано: аудит, затем короткие замеры и отдельная экспериментальная программа без изменения рабочего адаптера/CMake/DC/MC и без новых зависимостей. Пользователь разрешил запуски после ограничения AGENTS.md, затем сам обновил Release. Это не безусловное разрешение на длительные бенчмарки или изменение алгоритмов.

Оснований менять настройки рабочего адаптера по результатам опыта нет. MultiProcessCommunication оставить включённым. Обрезка и разреженные блоки — предложения. Smoothing/remeshing/сравнение с CGAL вне задачи. Git commit/push/pull не разрешены.

- Обновлённая Release-сборка: ParaView-only, 64³, пять повторов без экспорта. VF→Mesh медианы sphere=0.011 с, gyroid=0.030 с. Отдельные профили: filter=0.008/0.021 с; preparation=0.002/0.002 с; conversion=0.001/0.006 с. Округление до миллисекунд.

Прогрев каждого варианта, пять повторов с ротацией порядка; таймер только Update, проверки вне таймера.

Устойчивого существенного выигрыша не обнаружено; статистическая значимость не установлена.
- Исходник probe, бинарник, CSV и отчёты находятся в артефактах прежнего чата вне Git. На другом компьютере могут быть недоступны; в репозиторий не переносились. Не выдумывать отсутствующие детали.

## 6. Открытые вопросы и проблемы

- Пик памяти не измерен.
- Обрезка области и удаление пустых блоков могут изменить граничную обработку; нужны halo и проверка поверхности/связности. Одной проверки max(VF)>iso недостаточно.
- Несколько блоков сами по себе потоков не добавляют. Нужны корректные ghost VF, стандартные размеры, владение общими областями, согласование locator.
- Переиспользование входа может уменьшить preparation; требуется Modified() при изменении VF. Полный обход фильтра останется.
- Патчи dispatch один раз на блок, внутренний быстрый путь, пропуск областей и параллельная классификация — гипотезы без измеренного эффекта. Изменения ParaView не согласованы.
- При записи памяти уже изменены docs/architecture.md, docs/implementations.md, docs/running.md; агент их не менял, не перезаписывать.
