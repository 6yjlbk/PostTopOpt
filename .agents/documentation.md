# Рабочая память Documentation

## 1. Роль и область ответственности

Русскоязычная Markdown-документация PostTopOpt. Сверять описание с C++-кодом, использовать корректные формулы и терминологию вычислительной геометрии. Отделять реализацию от планов. Без отдельного задания не менять C++, CMake и тесты. Работать только со своей памятью.

## 2. Текущее состояние

Первоначально изучены существующие документы и выборочно исходники. Предложена организация документации; она ещё не согласована и не реализована. Текущая задача — создать память. При новой сессии читать этот файл и AGENTS.md, сверять заметки с кодом; после содержательной работы обновлять память. Не хранить секреты и персональные данные; использовать относительные пути.

## 3. Проверенные факты о проекте

- README.md направляет в docs/architecture.md, docs/running.md, docs/benchmark.md и docs/implementations.md.
- include/PostTopOpt.h и src/PostTopOpt.cpp: geometry::extract принимает функциональное поле либо CellScalarVolume; Backend включает Dc, Emilk, Mc, CgalDc, ParaViewAmr.
- src/PostTopOpt.cpp: ParaView получает элементные VF напрямую через адаптер; функциональный вход для него отклоняется исключением. Остальные методы получают densityField с порогом внутри поля и нулевым изоуровнем извлечения.
- src/CellScalarVolume.cpp содержит linearCellField и densityField. docs/architecture.md описывает трилинейную реконструкцию между центрами элементов, постоянное продолжение за крайними центрами, конвенцию f = tau - rho.
- src/DualContouring.cpp: регуляризованный QEF, ограничение ячейкой, контрольный и оптимизированный решатели. Собственные DC и emilk используют общий решатель, но разные плоскости (также указано в AGENTS.md).
- include/SurfaceExtraction.h содержит отдельный интерфейс extractSurface с cgal-dc-octree; его список методов отличается от Backend и CLI.
- apps/main.cpp: benchmark=true, repeats=5; compare выбирает dc и paraview-amr. Без benchmark — одно извлечение на метод; benchmark имеет прогрев и отдельный диагностический вызов.
- docs/benchmark.md: историческая серия 13 ноября 2026, исходные отчёты удалены пользователем. Замеры не воспроизводились в этом чате и не гарантируют скорость текущего кода.
- AGENTS.md: не запускать сборки, приложения и тесты до нового разрешения; не делать commit/push без запроса; не восстанавливать удалённые результаты. DC не гарантирует манифолдность, замкнутость и отсутствие самопересечений.

## 4. Принятые решения

Указания пользователя: поддерживать только .agents/documentation.md; относительные пути для синхронизации через Git; без отдельного запроса не выполнять commit, push или pull. При создании памяти разрешены только каталог .agents и собственный файл.

Предложение, ещё не согласованное: README.md — входная точка; docs/architecture.md — контракты и API; docs/algorithm.md — алгоритмы и различия методов; docs/mathematics.md — формулы; docs/running.md — CLI, форматы и метрики; docs/benchmark.md — методика и исторические результаты; docs/decisions.md — обоснования решений; docs/roadmap.md — планы; docs/implementations.md — внешний обзор. Атрибуция остаётся в third_party. Причина: architecture.md объединяет архитектуру и математику, benchmark.md — результаты и планы. Новые документы пока не созданы.
